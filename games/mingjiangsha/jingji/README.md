## 第一步做对了什么

难点只有一个：**鼠标悬浮会改变这张卡的样子**（你给的三张图就是三种程度）。

实测（模板统一取空闲态实拍，搜索范围就是那个窄 ROI）：

| 状态 | 分数 | 该不该认出 |
|---|---|---|
| 首页·空闲 | **1.000** | ✅ |
| 首页·弱悬浮 | 0.822 | ✅ |
| 首页·中悬浮 | 0.782 | ✅ |
| 首页·强悬浮 | 0.707 | ✅ |
| **竞技场页**（不在首页） | 0.382 | ❌ |
| **队伍面板**（不在首页） | 0.439 | ❌ |
| **准备态**（不在首页） | 0.439 | ❌ |

**正例最低 0.707，反例最高 0.439，中间空出 0.268。** 阈值取 0.55。

### 为什么一个模板就够（这跟直觉不一样）

我一开始做的是**两个模板**（空闲一个、悬浮一个），因为"悬浮会变样"听起来就该多备一个。
后来发现不必，关键在 **ROI 的第二个作用**：

`JINGJI_ROI` 只框住这一张卡，旁边的"房间/战没/煮酒"都在框外。于是阈值要回答的问题
**变了** —— 不是"这是不是竞技卡的某个特定姿态"（那才需要模板和姿态一一对应），
而只是"**这张卡在不在**"。

数据能说明这一点：**不套 ROI** 时全图次高分是 0.611（旁边的卡），留不出余量；
**套上 ROI** 之后反例最高只有 0.439，余量一下就出来了。

> 一般化的经验：**先想办法把"多分类"变成"二分类"，再谈调阈值。**
> 多做一个模板是下策；把搜索范围收窄往往更有效，也更好维护。

### 顺手排除掉的四个错误猜测

都实测过，全是否 —— 记下来免得以后再花时间：

* **不是尺度问题** —— 0.80~2.00 倍逐个扫，那三张图都在 **1.00~1.02** 处达到峰值；
  而且 2% 的尺度误差只值 0.07 分（1.000 → 0.933），解释不了 0.82；
* **不是压缩噪声** —— 实拍压成 JPEG q70 再匹配还有 0.996；
* **不是"缩小再放大"的往返重采样** —— 模拟 0.897 缩 + 1.115 放，自己匹配自己 0.991；
* **不是亮度/对比度** —— 平均亮度 128 vs 124、对比度 73 vs 76，几乎一样，
  而 TM_CCOEFF_NORMED 本来就能吃掉线性亮度变化。

所以那 18% 的差异是**结构性**的（卡片被挪动/重绘）—— 正是你说的那个悬浮效果。

### 待机动画不用管

卡片一直在动（光效扫过会让 38% 的像素变化），但模板分数稳在 **0.985 以上**：
2.8 秒内连拍 5 帧，分别是 1.000 / 0.992 / 0.987 / 0.994 / 0.985。
TM_CCOEFF_NORMED 对"整体叠一层光"这类变化是稳的。

## 首页的识别特征为什么用竞技卡本身

我量了四个候选，结论和直觉相反：

| 候选 | 实拍图上 | 三种悬浮状态图上 | 结论 |
|---|---|---|---|
| 顶部资源条 | 1.000 | 1.000 / 1.000 / 1.000 | ❌ 框进了会变的数字（2114、1.2万） |
| 底部功能栏 | 1.000 | 0.998 / 0.999 / 0.999 | ⚠️ 图标会挂红点角标，角标没了就失配 |
| 左上角头像 | 1.000 | **0.556 / 0.610 / 0.573** | ❌ 那个小人会动 |
| "一马当先"活动条 | 1.000 | 0.984 / 0.995 / 0.995 | ❌ 限时活动，15 天后没了 |

最后用**竞技卡本身**：它只存在于首页，而且和点击目标是同一张图 ——
页面身份和动作目标永远不会自相矛盾。

> **分数高不等于能用。** 顶部资源条分数最高，但它框进了会变的数字。
> 挑识别特征时问三个问题：它会不会变？会不会被别的状态影响？它消失之后怎么办？

## 为什么我没法自己点进去截图

这个 agent 环境拦掉了鼠标注入 —— 连最底层的 `SetCursorPos` 都返回 0 且不给错误码，
而截屏、窗口枚举、输入桌面都是通的：

```
SetCursorPos 返回: 0     GetLastError: 0     光标: 不动
本进程会话 1 / 前台进程会话 1    （不是会话隔离）
ClipCursor: 全屏                （不是被游戏锁了光标）
OpenInputDesktop: 句柄有效       （同一个输入桌面）
```

所以"自己点进去抓模板"这条路走不通。你在 DSH 外面跑脚本时是正常的。
